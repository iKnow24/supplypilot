# API contract and integration boundary

This file is the agreement between the frontend (`feat/frontend-ux`) and backend
(`feat/backend-optimizer`) work. Change it in its own small PR, reviewed by both founders,
before either side depends on the change.

## 1. Catalog file (exists now)

`data/seed/demo_catalog.json`, generated by `data/seed/generate_seed.py`.

- Python model: `services/optimizer/src/supplypilot_optimizer/catalog.py`
- TypeScript schema: `apps/web/src/lib/catalog/schema.ts`
- Both are strict. Adding a field means editing BOTH, then regenerating the seed.
- Money: integer cents. Quantities: positive decimal strings + unit code. Times: ISO-8601
  with offset. Weekdays: ISO (1 = Mon … 7 = Sun).

## 2. HTTP API (versioned under /v1)

| Method | Path | Status |
| --- | --- | --- |
| GET | `/v1/health` | Done (M1) |
| POST | `/v1/optimize` | M3 |

Draft `POST /v1/optimize` request (to be finalized at the start of M3):

```json
{
  "buyer_id": "org_sundaycrumb",
  "zone": "ORL-WP",
  "delivery_date": "2026-11-10",
  "lines": [{ "product_id": "prd_flour_ap_unbl", "quantity": "250", "unit": "lb" }],
  "preferences": { "excluded_supplier_ids": [], "preferred_supplier_ids": [], "allow_equivalences": true },
  "baseline": { "saved_list_id": "lst_sundaycrumb_weekly" }
}
```

Response: `status` (`optimal` | `infeasible`), `recommendation` (suppliers -> lines with packs,
pack price, line total, overbuy; per-supplier subtotal, fee, minimum check), `alternatives[]`,
`baseline` (or `null` with a reason), `excluded_offers[]` with reasons, `explanations[]`.

Once the Pydantic models exist, the frontend generates TS types from FastAPI's OpenAPI schema
(`openapi-typescript`), so nobody hand-copies response types.
